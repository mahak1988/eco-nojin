# اتصال CMS به بخش‌های دیگر پروژه

## مقدمه
این سند نحوه اتصال CMS به سایر ماژول‌های پروژه Econojin را توضیح می‌دهد. این اتصالات امکان مبادله داده، همگام‌سازی محتوا و ایجاد تعامل بین ماژول‌ها را فراهم می‌کند.

## ماژول‌های قابل اتصال

### 1. ماژول جلویی (Frontend)
- **هدف**: همگام‌سازی محتوای جدید با سایت جلویی
- **نحوه اتصال**: از طریق API endpoint مشخص
- **رویدادهای ارسالی**: ایجاد/به‌روزرسانی/حذف محتوا

### 2. ماژول احراز هویت (Authentication)
- **هدف**: همگام‌سازی اطلاعات کاربری و مجوزها
- **نحوه اتصال**: از طریق سرویس احراز هویت
- **رویدادهای ارسالی**: ایجاد/به‌روزرسانی/حذف کاربر

### 3. ماژول تجاری الکترونیک (E-commerce)
- **هدف**: ایجاد صفحات محصول و همگام‌سازی اطلاعات
- **نحوه اتصال**: از طریق API تجاری الکترونیک
- **رویدادهای ارسالی**: ایجاد/به‌روزرسانی/حذف محصول

### 4. ماژول پرداخت (Payment)
- **هدف**: ایجاد صفحات مربوط به پرداخت و اشتراک
- **نحوه اتصال**: از طریق سرویس پرداخت
- **رویدادهای ارسالی**: وضعیت پرداخت، اشتراک کاربر

## روش‌های اتصال

### 1. اتصال از طریق API
برای اتصال به هر ماژول، باید endpoint مربوطه را ثبت کنید:

```
POST /api/module-integration/connect
{
  "module": "frontend",
  "endpoint": "https://frontend.econojin.com/api"
}
```

### 2. استفاده از وب‌هوک‌ها
ماژول‌های دیگر می‌توانند وب‌هوک ثبت کنند تا از تغییرات محتوا مطلع شوند:

```
POST /api/module-integration/register-webhook
{
  "endpoint": "https://other-module.com/webhook",
  "events": ["content.create", "content.update"]
}
```

## امنیت

### مجوزهای دسترسی
- هر ماژول باید یک توکن دسترسی داشته باشد
- دسترسی به APIها از طریق میان‌افزار `module-connection` کنترل می‌شود
- سیاست `module-access` مجوزهای دسترسی را مدیریت می‌کند

### اعتبارسنجی
- تمام درخواست‌ها باید از منابع مجاز باشند
- توکن‌های ماژول باید معتبر باشند
- داده‌های ورودی باید اعتبارسنجی شوند

## رویدادهای یکپارچه‌سازی

سیستم یکپارچه‌سازی به این رویدادها پاسخ می‌دهد:

- `entry.create`: زمانی که محتوای جدیدی ایجاد می‌شود
- `entry.update`: زمانی که محتوا به‌روزرسانی می‌شود
- `entry.delete`: زمانی که محتوا حذف می‌شود

## سرویس‌های اصلی

### ModuleIntegrationService
این سرویس تمام عملیات اتصال به ماژول‌های دیگر را مدیریت می‌کند:

- `connectToFrontend()`: اتصال به ماژول جلویی
- `connectToAuth()`: اتصال به ماژول احراز هویت
- `syncContentToModules()`: همگام‌سازی محتوا با ماژول‌ها
- `receiveContentFromModules()`: دریافت محتوا از ماژول‌ها
- `registerWebhook()`: ثبت وب‌هوک برای دریافت اعلان

## مدل‌های داده

### IntegrationSetting
تنظیمات اتصال به هر ماژول را ذخیره می‌کند:

- module: نام ماژول (frontend, auth, ecommerce, payment)
- endpoint: URL endpoint ماژول
- isActive: وضعیت فعال بودن اتصال
- apiKey: کلید احراز هویت
- lastConnection: آخرین زمان اتصال

### RegisteredWebhook
وب‌هوک‌های ثبت شده توسط ماژول‌های دیگر را ذخیره می‌کند:

- endpoint: URL وب‌هوک
- events: لیست رویدادهایی که وب‌هوک باید دریافت کند
- isActive: وضعیت فعال بودن وب‌هوک

## استفاده عملی

### اتصال به ماژول جلویی
```javascript
const integrationService = strapi.service('module-integration-service');
await integrationService.connectToFrontend('https://my-frontend.com/api');
```

### همگام‌سازی محتوا
```javascript
await integrationService.syncContentToModules(
  contentData, 
  'api::page.page', 
  'create'
);
```

### دریافت محتوا از ماژول دیگر
```javascript
await integrationService.receiveContentFromModules(
  'ecommerce', 
  productData
);
```

## نکات مهم

- تمام اتصالات باید از طریق سیستم احراز هویت ماژول‌ها انجام شود
- باید مطمئن شوید که endpointهای ماژول‌های دیگر قابل دسترسی هستند
- برای عملکرد بهینه، توصیه می‌شود از CDN برای تحویل محتوا استفاده کنید
- همیشه باید محتوا را قبل از ذخیره یا ارسال اعتبارسنجی کنید
